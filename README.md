# Kenshi-Compain

Интерактивное сопровождение прохождений Kenshi и ведение их истории с помощью LLM. Здесь хранятся правила игровых сессий и летописи, документы кампаний, шаблоны возможных форм ответа и опубликованные данные игровых сохранений.

## Архитектура

Игровой компаньон помогает исследовать мир, оценивать состояние отряда, обсуждать тактику и стратегию, планировать действия и создавать художественные эпизоды. Игрок принимает решения; модель предлагает варианты, исследует последствия и отделяет предположения от подтверждённых результатов.

Летопись читает сохранённую историю, поддерживает справочник персонажей и создаёт литературные произведения. Она независима от игровой сессии и не является посредником при архивировании.

Общая база знаний `Kenshi. Bible` и внешние справочники предоставляют сведения о Vanilla, лоре, игровых механиках, картах и фракциях. Они не подтверждают события отдельного сохранения.

Роли могут реализовываться разными проектами ChatGPT или блокнотами Gemini. Обмена памятью между ними не предполагается: общим источником служит GitHub `main`.

## Источники и границы ответственности

| Раздел | Назначение |
|---|---|
| `docs/companion-guide.md` | Поведение игрового компаньона и выбор источников |
| `docs/chronicler-guide.md` | Исследование истории и литературная работа |
| `docs/session-protocol.md` | Актуализация состояния и фиксация завершённой сессии |
| `Campaign/` | Материалы прохождений: Хронология, текущая арка, билды, Библия, архив |
| `published/` | Автоматическая публикация состояния сохранения и скриншотов; только чтение |
| `templates/` | Примеры подходов и форм представления, не обязательные сценарии |
| `prompts/` | Конфигурации ролей для ChatGPT и Gemini; не игровой первоисточник |
| `sites/ROADMAP.md` | Возможное развитие интерфейса |

Внутри каталога кампании исходными ориентирами служат `Kenshi_Хронология.md`, `Kenshi_Текущая_арка.md`, `Kenshi_Архетипы_и_билды.md`, `archive/Kenshi_Библия.md` и `archive/sessions/`. Названия и дополнительные материалы конкретного прохождения определяются содержимым его каталога.

Справочники дают знания о возможностях игры; `published/` отражает последний доступный сейв; Хронология и сохранённые `S-YYYYMMDD-n.md` устанавливают подтверждённую историю; текущая арка содержит действующие цели и ещё не закрытые решения. У этих источников разные временные границы.

## Игровой цикл

Одна игровая сессия ведётся в одном чате до `[итог]`. `[ход]` обновляет оперативный контекст по новому опубликованному состоянию и свидетельствам игрока; `[сверка]` проверяет существенные противоречия только по запросу.

`[итог]` сам разрешает запись закрытой сессии `S-YYYYMMDD-n.md` и необходимых изменений Хронологии и рабочих документов в GitHub `main` одним согласованным коммитом. Сохранённая запись доступна следующему игровому чату и летописи напрямую. До успешной публикации нельзя объявлять сессию закрытой.

Остальные ориентиры запросов: `[глава]` — стратегическое планирование; `[этап]` / `[экспедиция]` — проработка направления или вылазки; `[прогресс]` — оценка развития; `[обсуждение]` — свободный аналитический диалог. Выбор объёма, числа вариантов, степени художественности и структуры происходит в контексте задачи, без предписанных количественных норм.

## Доставка данных

Игра → конвертер `kenshi-campaign-tech` → `published/` в GitHub → чтение LLM → сохранение канона в GitHub. Google Drive `Kenshi Compain. Docs` может служить зеркалом и каналом передачи материалов; не является отдельным каноническим архивом.

- `manifest.json` — идентификаторы снимка, ветка, время игры и статус проверки.
- `brief.md`, `squad.md`, `changes.md`, `timeline.jsonl` — сводка, персонажи, изменения и события.
- `current/index.json` и `current/` — навигация по детальным данным; `extended/` — расширенный слой.
- `screenshots/index.md` и изображения — навигация и визуальные свидетельства. Индекс не заменяет просмотр кадра.

Для публикации при отсутствии прямого доступа к GitHub может использоваться буфер `tmp/inbox/` на Google Drive. До подтверждённой записи такой пакет остаётся черновиком.
