# Kenshi-Compain

Интерактивное сопровождение прохождений Kenshi и ведение их истории с помощью LLM. Здесь хранятся руководства игрового компаньона и летописи, документы кампаний, формат архивной сессии и опубликованные данные игровых сохранений.

## Архитектура

Игровой компаньон помогает исследовать мир, оценивать состояние отряда, обсуждать тактику и стратегию, планировать действия и создавать художественные эпизоды. Игрок принимает решения; модель предлагает варианты, исследует последствия и отделяет предположения от подтверждённых результатов.

Летопись читает сохранённую историю, поддерживает справочник персонажей и создаёт литературные произведения. Она независима от игровой сессии и не является посредником при архивировании.

Общая база знаний `Kenshi. Bible` и внешние справочники предоставляют сведения о Vanilla, лоре, игровых механиках, картах и фракциях. Они не подтверждают события отдельного сохранения.

Основная среда игрового компаньона — Gemini Notebook; роли могут реализовываться также проектами ChatGPT. Обмена памятью между ними не предполагается: общим источником служит GitHub `main`. Особенности каждой среды описаны в настройках ролей в `prompts/`.

## Источники и границы ответственности

| Раздел | Назначение |
|---|---|
| `docs/companion-guide.md` | Задачи компаньона, источники, гайды главы и этапа, разбор переходов и анализ отряда |
| `docs/response-formatting.md` | Выбор формы ответа и средств представления |
| `docs/chronicler-guide.md` | Исследование истории и литературная работа |
| `docs/session-protocol.md` | Актуализация состояния и фиксация завершённой сессии |
| `docs/Kenshi_sources.md` | Каталог внешних источников об игре, механиках, лоре, картах и FCS |
| `docs/Kenshi_RU_EN.md` | Справочник названий русской локализации |
| `Campaign/` | Материалы прохождений: Хронология, текущая арка, билды, Библия, архив |
| `published/` | Автоматическая публикация состояния сохранения и скриншотов; только чтение |
| `templates/template-session.md` | Формат архивной записи закрытой сессии |
| `prompts/` | Конфигурации ролей для ChatGPT и Gemini; не игровой первоисточник |
| `sites/ROADMAP.md` | Возможное развитие интерфейса |

Внутри каталога кампании исходными ориентирами служат `Kenshi_Хронология.md`, `Kenshi_Текущая_арка.md`, `Kenshi_Архетипы_и_билды.md`, `archive/Kenshi_Библия.md` и `archive/sessions/`. Названия и дополнительные материалы конкретного прохождения определяются содержимым его каталога.

Справочники дают знания о возможностях игры; `published/` отражает последний доступный сейв; Хронология и сохранённые `S-YYYYMMDD-n.md` устанавливают подтверждённую историю; текущая арка содержит действующие цели и ещё не закрытые решения. У этих источников разные временные границы.

## Игровой цикл

Одна игровая сессия ведётся в одном чате до `[итог]`. Новый сейв, выбор главы, вход в регион и любые вопросы игрок сообщает обычной речью; компаньон отвечает по `docs/companion-guide.md`.

`[итог]` — единственная служебная команда. Она разрешает запись закрытой сессии `S-YYYYMMDD-n.md` и необходимых изменений Хронологии и рабочих документов в GitHub `main` одним согласованным коммитом — напрямую или через пакет приёма конвертера, если среда не пишет в GitHub. Сохранённая запись доступна следующему игровому чату и летописи. До успешной публикации сессия остаётся открытой.

## Доставка данных

Игра → конвертер `kenshi-campaign-tech` → `published/` в GitHub и зеркало на Google Диске → чтение LLM → сохранение канона в GitHub. Зеркало Диска (Markdown-файлы `published/` и `Campaign/`, формат — `docs/gdrive-sync.md` конвертера) служит источниками Gemini Notebook; канон остаётся в GitHub `main`.

Конвертер публикует технические данные без аналитики; значимость изменений, переходы и выводы определяет модель. Форматы и семантика машинных данных `published/` задаются строгим [контрактом `kenshi-campaign-tech`](https://github.com/asaf1n/kenshi-campaign-tech/blob/main/docs/data-contract.md) и связанными схемами. Наличие файлов сверяется с `manifest.json`; игровая методология в `docs/companion-guide.md` и `docs/session-protocol.md` регулирует **интерпретацию** данных и запись истории, не заменяя контракт.

- `manifest.json` — идентификаторы снимка, ветка, время игры и статус проверки.
- `brief.md`, `squad.md`, `changes.md`, `timeline.jsonl` — сводка, персонажи, изменения и события.
- `current/index.json` и `current/` — навигация по детальным данным; `extended/` — расширенный слой.
- `screenshots/index.md` и изображения — навигация и визуальные свидетельства. Индекс не заменяет просмотр кадра.
- `screenshots/feed.md` и `annotations.jsonl` — машинная разметка кадров: день и время с экрана, выбранный персонаж, задачи. Публикуются при распознанном тексте; это ориентиры, а не подтверждённые события.

При отсутствии доступа к записи в GitHub компаньон готовит пакет приёма; игрок сохраняет его в `tmp/inbox/` на Диске, конвертер переносит его в `main` командой `ingest-inbox`. Пока пакет не принят в GitHub, он остаётся черновиком.
