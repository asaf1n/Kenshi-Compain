# Kenshi-Compain

Материалы для работы с LLM в роли игрового компаньона и автора летописи кампании по Kenshi: актуальное состояние игры, канон прохождений, режимы диалога и шаблоны ответов.

## Архитектура проектов

**ChatGPT:** на каждое прохождение создаются два отдельных проекта: **игровая сессия** (`prompts/project-instructions.md`) и **летопись / Расширенная повесть** (`prompts/project-chronicle.md`). Одна игровая сессия проходит в одном чате до `[итог]`. **Игровой `[итог]` напрямую коммитит закрытую сессию и необходимые изменения Канвы/арки в GitHub `main`;** следующий игровой чат и независимый проект летописи читают те же архивные файлы из GitHub. Обязательной передачи между чатами через память или промежуточный литературный чат нет. Для Gemini аналогичные функции распределены между перечисленными ниже блокнотами; общая база знаний остаётся отдельной.

1. **`Kenshi Compain. <Campaign Name>`** — блокнот отдельного прохождения (`prompts/notebook-sessions.md`): интерактивное ведение игровой сессии, тактика, планирование глав и этапов, короткие художественные вставки (1–3 абзаца) по ходу событий и выпуск готового артефакта сессии в режиме `[итог]`.

2. **`Kenshi Compain. Летопись <Campaign Name>`** — отдельный проект/блокнот (`prompts/project-chronicle.md` / `prompts/notebook-chronicle.md`): чтение архива GitHub за любой период, при необходимости историческая реконструкция, написание и поэтапное расширение повести (`archive/povest/`). Литературная работа не блокирует новые игровые сессии.

3. **`Kenshi. Bible`** — общая база знаний по игре Kenshi (Vanilla): официальные источники, данные FCS, механики прокачки и боя, карты, фракции, World States, лор мира и структура файлов сохранений.

## Поток данных

1. **Игра → конвертер → `published/` в GitHub → LLM / Google Notebook → Google Drive / Notion / внешние хранилища.**

2. Между выгрузками в Git в Gemini рабочие документы могут храниться в источниках блокнотов, а в ChatGPT текущая сессия ведётся в одном чате с видимыми контрольными точками. Память чата не гарантирует сохранение оригиналов; используйте `docs/session-protocol.md` и внешнее сохранение.

3. По команде «выгрузка для Git» формируется пакет обновлённых файлов. Если прямая запись в GitHub недоступна, игрок сохраняет его в `tmp/inbox/` на Google Диске; конвертер принимает пакет командой `ingest-inbox`, фиксирует в `main` и переносит в `tmp/processed/`.

4. Google Диск `Kenshi Compain. Docs` повторяет пути репозитория: `published/` (высокоуровневый срез и кадры), `Campaign/<кампания>/` (зеркало зафиксированного канона, вручную не редактируется), `tmp/` (буфер: `inbox/`, `checkpoints/`, `processed/`).

## Состояние игры (`published/`)

Выгрузка конвертера сохранений (только чтение):

* `manifest.json` — игровое время (`game_time`), активная ветка (`branch_id`), метаданные выгрузки.

* `brief.md` — оперативная сводка состояния отряда, казны, баз, исследований и мировых статусов.

* `squad.md` — полный ростер участников, характеристики, навыки, здоровье, протезы, экипировка и нагрузка.

* `changes.md` — читаемая сводка дельты с событиями промежуточных снимков; `changes.json` — та же дельта для программного чтения.

* `current/index.json` — индекс шардов текущего состояния (бойцы, постройки, обзор мира).

* `extended/current.json` — расширенный снимок мира для выборочного чтения.

* `locations.json` — координаты и статус поселений.

* `timeline.jsonl` — хронологическая лента подтверждённых событий.

* `world_reference.json` — географический и фракционный справочник.

* `screenshots/index.md` — новые кадры снимка и архивный хвост с первичной разметкой и ссылками; `screenshots/index.json` — те же метаданные для программного чтения, поле `new_frames` перечисляет новые кадры. Для визуальной оценки требуется открыть сами изображения.

* `screenshots/screenshots_latest.pdf` — новые кадры с текстовой шапкой для Gemini Notebook; файл есть только на Google Диске, в GitHub его нет.

**Два рабочих действия:** `[ход]` объединяет сейв и контекст текущего чата в одно оперативное состояние; `[итог]` по запросу закрывает сессию и после сохранения обновляет канон. `[сверка]` — сервисная проверка противоречий только по запросу, не обязательная стадия каждого сохранения. `Сверено до:` означает границу зафиксированной истории.

## Режимы работы

| Метка | Шаблон | Назначение | 
| ----- | ----- | ----- | 
| `[глава]` | `templates/template-chapter.md` | Макро-планирование маршрута из нескольких этапов по 1–2 большим территориям: лор-вступление (2–3 абзаца), возможности прокачки, боссы, уникальные предметы, маршрут и сжатие прошлой главы в Канве | 
| `[этап]` / `[экспедиция]` | `templates/template-expedition.md` | Геймплейный план и гайд по целевой локации/сектору: лор местности (1–2 абзаца), опасности среды, цели интереса, тренировочный потенциал и варианты маршрута | 
| `[ход]` | `templates/template-turn.md` | Проверка нового сейва и скриншотов, визуальный анализ доступных кадров, тактическая развилка, значимое событие или сводка | 
| `[прогресс]` | `templates/template-progress.md` | Оценка боеспособности колонны, выполнение целевых билдов и динамика прокачки; текстовые рекомендации визуализации | 
| `[обсуждение]` | `templates/template-discussion.md` | Разбор механик игры, модов, лора и стратегических компромиссов | 
| `[сверка]` | `templates/template-reconciliation.md` | Сервисная проверка противоречий и согласование точечных правок канона только по запросу | 
| `[итог]` | `templates/template-session.md` | Проверка и непосредственное сохранение `S-YYYYMMDD-n`, Канвы и подтверждённых правок в GitHub `main` одним коммитом; подтверждение публикации |
