# Kenshi-Compain

Интерактивное сопровождение прохождений Kenshi и ведение их истории с помощью LLM. Здесь хранятся руководства игрового компаньона и летописи, документы кампаний, формат архивной сессии и опубликованные данные игровых сохранений.

[Картографическая схема](sites/map/index.html) — автономная карта регионов, локаций и положения отряда. По умолчанию показывает текущий `published/` (запуск через HTTP-сервер из корня репозитория: `python -m http.server`, адрес `/sites/map/index.html`); без сервера выберите одновременно `manifest.json`, `world_reference.json`, `locations.json` и `location_registry.json` одного выпуска (реестр — если он указан в манифесте); можно добавить `Campaign/Хроники Хот Лон/locations_progress.json`. Встроенных снимков нет. Секретные локации скрыты по умолчанию. Цепочки регионов показывают только общие границы по растру игры, а разрыв остаётся разрывом. Доступны экспорт SVG и сводка для чата.

## Архитектура

Игровой компаньон помогает исследовать мир, оценивать состояние отряда, обсуждать тактику и стратегию, планировать действия, а по просьбе игрока — писать художественные эпизоды по подтверждённым событиям. Игрок принимает решения; модель предлагает варианты, исследует последствия и отделяет предположения от подтверждённых результатов.

Летопись читает сохранённую историю, поддерживает справочник персонажей и создаёт литературные произведения. Она независима от игровой сессии и не является посредником при архивировании.

Справочники проекта (`docs/reference/`) и внешние источники (`docs/Kenshi_sources.md`) дают сведения о механиках, мире, лоре и фракциях; события отдельного сохранения они не подтверждают.

Основная среда игрового компаньона и летописи — проекты ChatGPT. Основное хранилище — GitHub `main`; действующие инструкции проектов лежат в `prompts/`.

Внутри каталога кампании исходными ориентирами служат `Kenshi_Хронология.md`, `Kenshi_Текущая_арка.md`, `Kenshi_Архетипы_и_билды.md`, `locations_progress.json`, `archive/Kenshi_Библия.md` и `archive/sessions/`. Справочники дают знания о возможностях игры; `published/` отражает последний доступный сейв; Хронология и сохранённые `S-YYYYMMDD-n.md` устанавливают подтверждённую историю; текущая арка содержит действующие цели, ещё не закрытые решения и наблюдения, не сведённые в Хронологию. У этих источников разные временные границы.

## Игровой цикл

Открытый игровой период может длиться несколько чатов; его наблюдения сохраняются в текущей арке. `[gamedata_export]` — необязательная метка автоматически доставленной выгрузки, не команда публикации истории. Игровые сообщения формулируются свободно, обычной речью. Единственная команда закрытия периода — `[итог]`: сначала компаньон показывает проект архивной сессии и перечень правок для утверждения игроком, затем после явного подтверждения публикует согласованную редакцию. Единственный нормативный порядок, включая откаты и проверку записи, — [`docs/session-protocol.md`](docs/session-protocol.md). После публикации игра продолжается.

## Доставка данных

Игра → конвертер `kenshi-campaign-tech` → `published/` в GitHub → чтение LLM из GitHub → `[итог]` коммитом в `main`.

Конвертер публикует технические данные без аналитики; значимость изменений, переходы и выводы определяет модель. Форматы и семантика машинных данных `published/` задаются строгим [контрактом `kenshi-campaign-tech`](https://github.com/asaf1n/kenshi-campaign-tech/blob/main/docs/data-contract.md) и связанными схемами. Наличие файлов сверяется с `manifest.json`; игровая методология в `docs/companion-guide.md` и `docs/session-protocol.md` регулирует **интерпретацию** данных и запись истории, не заменяя контракт.

- `manifest.json` — идентификаторы снимка и кампании, время игры, признак перезагрузки, статус проверки и состав артефактов.
- `brief.md`, `squad.md` — сводка и персонажи; `changes.md` и `changes.json` — изменения к предыдущему снимку; `timeline.jsonl` — события по цепочке снимков (последние 20 переходов).
- `locations.json` — положение персонажей и зданий относительно поселений и регионов; `world_reference.json` — справочник мира (поселения, регионы); `location_registry.json` (`kenshi-location-registry/3`) — открытость мест `discovered` из сейва и отметки зачистки `cleared` из `Campaign/<кампания>/locations_progress.json`.
- `tables/` — таблицы для сверки и расчётов: состав, экипировка всех экземпляров (надетая, в рюкзаках, на складах), инвентари, склады, расы, цены, дипломатия, уникальные NPC, реакции мира; словарь колонок — `tables/index.md`.
- `extended/current.json` — полный срез сейва одним файлом; открывается, когда данных таблиц не хватает.
- `screenshots/index.md`, `index.json` и изображения за последние 7 суток — навигация и визуальные свидетельства. Индекс не заменяет просмотр кадра.
- `screenshots/feed.md` и `annotations.jsonl` — машинная разметка кадров: день и время с экрана, выбранный персонаж, задачи. Публикуются при распознанном тексте; это ориентиры, а не подтверждённые события.
