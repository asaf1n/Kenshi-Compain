# ADR 0001: Картографический слой и просмотрщик Kenshi

## Статус
Accepted по решению игрока от 2026-11-08 (варианты (б) и «перенос кода»). `git push` ветки `feature/cartography` выполняется только после повторного ревью.

## Дата
2026-11-08 (коррекция после приёмки a1e0099)

## Контекст
Нужна карта в игровой системе координат: регионы, подтверждённые локации, положение персонажей текущего выпуска `published/` и сравнение двух цепочек регионов главы XI (Пойма → Гиблые земли).

## Исходные данные

- `data/newland/land/areasmap.tga`: 256×256, **24-битный RGB**, тип 2. Цвет пикселя — индекс записи `BIOME_GROUP` (`type_id=95`) из палитры `regions` справочника мира. Пиксель — 1152 игровые единицы. Файл принадлежит игре; в репозиторий не кладётся.
- Конвертер сохраняет растр в `data/world/<world_ref_id>.json` (своего репозитория) как `regions_map.rle` (пары `index`/`length` и признак `border`) и хеш исходного файла в `source_hashes`. Файл локальный, вне git.
- `docs/reference/regions_map.svg`: 69 сглаженных контуров, получены ранее из растра, генератора в репозитории нет. **Идентификаторов регионов в SVG нет**: регион задан только текстом `<title>Название (name_en)</title>`. Исходный файл не изменяется; если нужны `id`, они генерируются в производном файле при экспорте.
- Игровых дорог нет (`roads.level` — заглушка). Любая линия между регионами не является маршрутом.

## Решение (принято по коррекции)

1. **Снимок по умолчанию — текущий `published/`.** Просмотрщик читает `../../published/{manifest,world_reference,locations}.json`. Встроенного исторического снимка нет. Без HTTP-сервера (`file://`) выпуск выбирается вручную тремя файлами. Замена выпуска другой кампании, ветки или снимка требует подтверждения; слои разных снимков не объединяются (`select_release` в Python требует явного `snapshot_id`).
2. **Коридор — цепочка регионов, не точек.** Пойма → Гиблые земли: вариант А через Возрождение, вариант Б через Руку Окрана (Край Мира — локация в регионе Arm of Okran). Каждый шаг — пара регионов. Есть общая 4-связная граница в растре → `border`, нет → `gap` («разрыв: общей границы нет»). Цепочка не достраивается промежуточными регионами, между регионами не рисуется линия, расстояния и оценки проходимости или безопасности не считаются. Регионы цепочек выделяются контуром.
   Результат на текущей геометрии: А = Пойма→Возрождение `border`, Возрождение→Гиблые земли `gap`; Б = оба шага `gap`.
3. **Растр в репозитории не хранится.** Встроенный RLE удалён. В репозитории остаются только производные артефакты: `regions_map.svg` (контуры) и `regions_adjacency.json` (таблица соседства 69 регионов с хешами `raster_source_sha256`, `raster_cells_sha256`, `adjacency_sha256`, алгоритм `rle-four-neighbors/1`). Таблица перестраивается в конвертере командой `python -m tools.cartography --build-adjacency --world-source <data/world/<id>.json>`.
4. **Две проверки геометрии (в `kenshi-campaign-tech`).** Фикстурный режим: хеши SVG и таблицы, малые растры для алгоритма соседства. Локальный режим (`--local` или `--world-source`): хеш исходного растра, хеш декодированных ячеек, пересчёт соседства, сверка палитры и регионов локаций/персонажей с растром. Только локальный режим возвращает `world_source_verified=true`; CLI включает его флагом `--local` (`data/world/<world_ref_id>.json` конвертера) либо явным `--world-source`.

## Решения игрока

1. **Растр и проверка геометрии — вариант (б).** Генерация и проверка геометрии находятся в `asaf1n/kenshi-campaign-tech` (`tools/cartography.py`, `tests/test_cartography.py`, `assets/cartography/`). Растр не встраивается ни в один репозиторий: проверка читает `data/world/<world_ref_id>.json` локально; в CI работает фикстурный режим (малые растры и малый выпуск в памяти).
2. **Код картографии переносится в `kenshi-campaign-tech`.** В `Kenshi-Compain` остаются просмотрщик `sites/map/index.html` и доставляемые производные `docs/reference/regions_map.svg`, `docs/reference/regions_adjacency.json`. Python-кода и unittest в этом репозитории нет.
3. **Доставка.** `deliver-companion` доставляет `published/` независимо от карты и дополнительно записывает оба артефакта в `docs/reference/` в коммите выгрузки. Перед записью артефактов проверяется совместимость `sites/map/index.html`: граф, контуры, цепочки, `world_ref_id`, отсутствие растра и формулировок о проходимости, загрузка `../../published/`, подтверждение замены выпуска, предупреждение «устаревший снимок». Состояние карты — отдельное поле отчёта `cartography` = `ok` | `incompatible` | `skipped` с причиной в `cartography_reason`; несовместимый или нечитаемый просмотрщик блокирует запись артефактов, но не доставку `published/`. `status=failed` — только при сбое доставки `published/`.
4. **Сопоставление регионов** — по `name_en`/`sid`. `The Iron Trail` отображается как «Железный шельф».
5. **История.** Ветка `feature/cartography` сведена в один коммит и растр не добавляет; критерий — «ветка растр не добавляет». Унаследованная история `main` (уже на origin) содержит `regions_map.rle` в `published/world_reference.json` в 19 коммитах прежних выпусков. Решение игрока: история `main` не переписывается, force-push не выполняется.

Проверки, команды и правила доставки описаны в `docs/cartography.md` репозитория `kenshi-campaign-tech`.

## Границы данных

- Подтверждённая координата или регион, цепочка регионов по растру и подтверждённый переход — разные слои. Слой переходов пуст: источника со ссылками на сессии нет. При `movement.valid=false` векторы смещения не рисуются.
- Секретные локации скрыты по умолчанию.
- `unknown` не получает точку на карте.
- Персонажи различаются по `id`; одноимённые остаются разными записями.
- Регион `The Iron Trail` везде отображается как «Железный шельф»; `Fog Islands` — «Острова тумана».
- Сторонние тайлы и игровые текстуры (`GUI_Map.dds`, `fullmap.tif`) не используются.

## Система координат

`X, Z ∈ [-147456, 147456)`; `svg_x = (X + 147456) / 1152`, `svg_y = (Z + 147456) / 1152`; `Z` растёт на юг, строка растра `py=0` — юг: `px = ⌊svg_x⌋`, `py = 255 − ⌊svg_y⌋`.
