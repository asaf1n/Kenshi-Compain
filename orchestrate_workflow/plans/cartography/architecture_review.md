## 2. Система координат: решение корректно, контракт нужно дополнить

В [ADR:56](</C:/Users/artem/Kenshi Compain/docs/adr/0001-cartography.md:56>) правильно указано:

```text
svg_x = (X + 147456) / 1152
svg_y = (Z + 147456) / 1152
```

Для текущей карты:

- X возрастает на восток;
- Z возрастает на юг;
- Y — высота, в плоской карте не используется;
- SVG имеет `viewBox="0 0 256 256"`, его вертикальная координата возрастает вниз;
- допустимый диапазон игровых X/Z: `[-147456, 147456)`.

**Дополнительный переворот `svg_y` ошибочен:** существующий SVG уже ориентирован севером вверх.

Различие между SVG и RLE должно быть записано явно:

```text
px = floor(svg_x)
py = 255 - floor(svg_y)
rle_index = py * 256 + px

X = 1152 * svg_x - 147456
Z = 1152 * svg_y - 147456
```

Пиксель — область, поэтому преобразование координаты в индекс пикселя необратимо. Для обратного преобразования следует договориться о центре ячейки:

```text
X_center = 1152 * (px + 0.5) - 147456
Z_center = 1152 * (255 - py + 0.5) - 147456
```

## 3. Граф соседства: подтверждён, но не описывает проходимость

По полному RLE независимо восстановлен граф четырёхсвязного соседства:

| Пара регионов | Общая граница, рёбер ячеек |
|---|---:|
| Пойма — Возрождение | 11 |
| Скорняков край — Гиблые земли | 36 |
| Рука Окрана — Скорняков край | 3 |
| Возрождение — Гиблые земли | 0 |
| Рука Окрана — Гиблые земли | 0 |

Подтверждены 69 регионов в растре и два исключаемых кода: `0x000000`, `0x329999`. У Смирения общих границ с другими регионами нет.

Для демонстрации сравнения подходят следующие **предлагаемые цепочки регионов**, у которых все последовательные пары имеют общую границу:

1. Пойма → Возрождение → Окранова гордость → Скорняков край → Гиблые земли.
2. Пойма → Скрытый лес → Рука Окрана, с ориентиром Край Мира → Скорняков край → Гиблые земли.

Это подтверждает только топологическую связность цепочек. Оно не подтверждает проход через конкретную точку границы, доступность Края Мира по выбранной линии, безопасность или длину путешествия.

**Требование Sol:** различать контрольные точки пользователя и последовательность регионов. Сообщение для несоседних регионов — «нет общей границы в растре», а не «маршрут непроходим». Промежуточные регионы нельзя незаметно достраивать автопоиском: он исключён из MVP.

### AR-01. Правовая чистота производных контуров не установлена

На официальном сайте Lo-Fi Games найдено разрешение на монетизацию видео YouTube/Twitch. Распространение извлечённой картографической геометрии этим текстом не охвачено. Условия сайта относятся к материалам сайта; считать их лицензией игровых ресурсов также нельзя. [Lo-Fi Games: Contact](https://lofigames.com/contact-us/), [Terms of Service](https://lofigames.com/terms-of-service/).

У `alexusfree/kenshimap` GitHub возвращает `license: null`. Корректный вывод — **разрешение на нужное использование не подтверждено**. Сам по себе публичный репозиторий не предоставляет общей лицензии на копирование и распространение материалов. [Репозиторий](https://github.com/alexusfree/kenshimap), [GitHub: licensing a repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository).

**Условие закрытия:**

- раздельно описать права на собственный код, игровую текстуру, производную геометрию и материалы модов;
- убрать утверждение о гарантированной «защите от нарушения авторских прав»;
- зафиксировать решение игрока по существующему публичному SVG и будущим производным материалам;
- до решения не включать новые производные материалы в публичную поставку.

Решение игрока определяет дальнейшее действие проекта, но само по себе не заменяет разрешение правообладателя. Уже существующий SVG самостоятельно удалять нельзя — это прямо запрещено исходным заданием.

### AR-02. Не определён воспроизводимый источник геометрии

**Место:** [ADR:36](</C:/Users/artem/Kenshi Compain/docs/adr/0001-cartography.md:36>), [ADR:54](</C:/Users/artem/Kenshi Compain/docs/adr/0001-cartography.md:54>).

Публичный `world_reference.json` действительно не содержит `regions_map` и `source_hashes`. Существующий SVG содержит 69 контуров, но не содержит `world_ref_id` или структурированных метаданных происхождения. Атлас — текстовый справочник, а не определённый машинный интерфейс графа.

Поэтому сейчас нельзя надёжно установить совместимость загруженного выпуска и контуров или воспроизвести обновление при смене мира.

**Условие закрытия:**

- назначить полный локальный `data/world/<world_ref_id>.json` первичным входом генерации;
- считать граф по исходному RLE, до сглаживания;
- определить версионируемый формат производного картографического пакета вне `published/`;
- включить в него `world_ref_id`, параметры координат, происхождение растра, версию алгоритма, идентификаторы регионов и граф;
- при несовпадении мира отключать соответствующий слой и проверку соседства с явным объяснением;
- установить воспроизводимую команду сборки.

SVG должен оставаться представлением данных. Нельзя вычислять истинное соседство по пересечениям сглаженных контуров или поддерживать граф вручную параллельно растру.

### AR-04. Не определена целостность загружаемого выпуска

**Место:** [ADR:43](</C:/Users/artem/Kenshi Compain/docs/adr/0001-cartography.md:43>), [ADR:58](</C:/Users/artem/Kenshi Compain/docs/adr/0001-cartography.md:58>).

В действительном контракте:

- `game_time`, `branch_id`, `campaign_id` берутся из manifest;
- `locations.json` содержит `snapshot_id` и `world_ref_id`, но не время и ветку;
- `world_reference.json` относится к миру, а не к отдельному снимку;
- у `spatial_groups` нет собственной координаты: есть участники и пространственная принадлежность.

ADR не задаёт правила сборки этих сущностей. Поочерёдный Drag-and-Drop или встроенный fallback могут привести к смешению разных выпусков.

**Условие закрытия:**

1. Загружать кандидатный набор целиком и заменять активный набор только после проверки.
2. Проверять форматы, необходимые поля, `validation.status`, совпадение `snapshot_id` manifest/locations и `world_ref_id` всех связанных слоёв.
3. Разделять несовместимые кампании, ветки и снимки.
4. Встроенный пример явно обозначать историческим примером; не подменять им повреждённый текущий набор.
5. Для групп показывать участников либо явно обозначенный вычисленный центр. Центр группы не выдавать за координату из сохранения.
6. Для `unknown` сохранять запись в списке без фиктивной точки на карте.
7. При `movement.valid=false` не рисовать перемещение как подтверждённое сравнение.

Без сети инструмент может показать время загруженного выпуска, но не доказать отсутствие более нового. Предупреждение об устаревании должно опираться на доступный baseline либо явно указанное правило.

### AR-05. Обоснование места реализации противоречиво

**Место:** [ADR:28–46](</C:/Users/artem/Kenshi Compain/docs/adr/0001-cartography.md:28>), [AGENTS.md:3](</C:/Users/artem/Kenshi Compain/AGENTS.md:3>).

Вариант А отклонён на предположении, что генератор в техническом репозитории обязательно меняет публикационный контракт. Это неверно: самостоятельный генератор может читать существующий полный справочник и создавать локальный результат вне `published/`, не затрагивая publisher, схему или `WORLD_DROPPED_KEYS`.

Одновременно ADR размещает Python-утилиту и тесты в игровом репозитории, действующий контракт которого исключает технические конвертеры, парсеры и тесты. Исходное задание предусматривает новый просмотрщик, но ADR не разрешает эту несогласованность границ.

**Предпочтительная корректировка:**

- генератор, вычисление графа и Python-проверки — в `kenshi-campaign-tech`;
- интерфейс просмотра — в `Kenshi-Compain/sites/map/`;
- передача геометрии — отдельным производным пакетом, с учётом AR-01;
- существующие публикационные контракты и доставка `published/` сохраняются.

Размещение всего в игровом репозитории возможно только после явного согласования новой границы и синхронизации инструкций.

Дополнительно обнаружено расхождение документации: AGENTS объявляет весь `docs/` локальным, но фактический `.gitignore` исключает только `docs/CHRONOLOGY.md`, а SVG и атлас уже отслеживаются Git. Правило публикации следует согласовать адресно, без массового удаления документов.

## 5. Автономная работа и выбор технологии

**SVG/Vanilla JS — достаточный вариант для MVP.** Leaflet не обязателен: он добавляет зависимость и собственные соглашения о координатах, не решая вопросы происхождения данных или прав. Его официальная документация отдельно предупреждает о различии единиц карты и пикселей изображения. [Leaflet: non-geographical maps](https://leafletjs.com/examples/crs-simple/).

Оговорка ADR о `file://` правильна: браузер может рассматривать локальные файлы как разные непрозрачные источники и блокировать `fetch`. Поэтому загрузка через выбор файлов должна быть штатным автономным сценарием. [MDN: Same-origin policy](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Same-origin_policy).

Для Sol следует закрепить:

- HTML открывается непосредственно с диска;
- выбор полного набора файлов доступен без сервера;
- скрипты, стили и необходимые ресурсы доступны локально;
- сетевой режим, если появится, остаётся дополнительным;
- SVG-экспорт самодостаточен: без внешних шрифтов, картинок и ссылок на локальные ресурсы;
- загружаемые названия и подписи вставляются как текст, а не исполняемая HTML/SVG-разметка;
- вычисления в CLI и браузере имеют одинаковые правила; Python-проверки не заменяют проверку реального браузерного сценария.

Заявления «максимальная надёжность» и «100% тестируемость через unittest» из ADR следует заменить конкретными критериями поведения.
