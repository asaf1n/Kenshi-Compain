# План: Внедрение сессионного архива и горячего набора кампании

Статус: черновик  
Репозиторий: `Kenshi Compain`  
Дата создания: 2026-11-03  
Целевая ветка: `main`

## 1. Цели плана

1. Разделение данных кампании на два слоя: компактный «горячий набор» постоянного контекста ($\le$ 37 000 символов суммарно) и неизменяемый «архив сессий» (`archive/`).
2. Обеспечение принципа «один факт — одно место»: горячий набор содержит указатели на ID архива (`S-...`, `D-...`, `E-...`, `B-...`) без дублирования фактов и пересказов.
3. Внедрение режима компаньона `[итог]` для фиксации сессий (журнал фактов + художественное повествование + правки горячего набора) и обновление сопутствующих режимов (`[сверка]`, `[хроника]`, `[ход]`, `[глава]`).
4. Актуализация нормативной документации (`docs/CHRONOLOGY.md`, `AGENTS.md`, `README.md`, `prompts/01-COMPANION-SYSTEM.md`).
5. Безопасная миграция текущих данных кампании «Хроники Хот Лон» без потерь фактов (с обязательным утверждением diff игроком перед записью).

## 3. Критичные лимиты горячего набора

- `Campaign/<кампания>/Kenshi_Текущая_арка.md` $\le$ 12 000 символов.
- `Campaign/<кампания>/Kenshi_Отряд.md` $\le$ 15 000 символов.
- `Campaign/<кампания>/Kenshi_Канва.md` $\le$ 10 000 символов.
- Суммарный объем горячего набора: $\le$ 37 000 символов (~9 000 токенов), что гарантирует стабильную загрузку в любые LLM-интерфейсы.

## 4. Инварианты и стоп-условия

- Каталог `published/` — СТРОГО READ-ONLY.
- Каталог `Campaign/` — редактирование и перенос файлов ТОЛЬКО после показа полного diff игроку и получения его явного согласия (Точка остановки 2).
- Все определения режимов взаимодействия строго инкапсулированы в `templates/` (SSOT).
- Коммиты выполняются локально с трейлером фактического агента-соавтора. `git push` не выполняется без команды игрока.
