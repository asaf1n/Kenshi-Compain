# План: Внедрение сессионного архива и горячего набора кампании

Статус: черновик  
Репозиторий: `Kenshi Compain`  
Дата создания: 2026-11-03  
Целевая ветка: `main`

## 1. Цели плана

1. Разделение данных кампании на два слоя:
   - Компактный динамический «горячий набор» постоянного контекста ($\le$ 37 000 символов суммарно по трем оперативным документам): текущее положение, действующие стратегические решения, открытые нити, целевые билды и канва-указатель.
   - Неизменяемый «сессионный архив» (`archive/`): расширенные журналы сессий, художественный нарратив, библия мира и неизменяемые исторические материалы (`archive/legacy/`).
2. Обеспечение принципа «один факт — одно место»: отсутствие дублирования фактов и пересказов внутри горячего набора; горячий набор содержит компактные указатели на идентификаторы архива (`S-...`, `D-...`, `E-...`, `B-...`).
3. Внедрение режима компаньона `[итог]` для фиксации сессий (журнал фактов + художественное повествование + правки горячего набора) с расширением исключения из запрета «синдрома аудитора» для блока сессионного журнала.
4. Обновление сопутствующих режимов взаимодействия (`[сверка]`, `[хроника]`, `[ход]`, `[глава]`) в каталоге `templates/` (SSOT структуры ответов).
5. Актуализация нормативной документации (`docs/CHRONOLOGY.md`, `AGENTS.md`, `README.md`, `prompts/01-COMPANION-SYSTEM.md`).
6. Безопасная миграция данных кампании «Хроники Хот Лон» без потерь сюжетных нитей и фактов.

## 3. Состав и лимиты горячего набора

Динамический горячий набор (изменяется в игровом цикле):
- `Campaign/<кампания>/Kenshi_Текущая_арка.md` $\le$ 12 000 символов (LF).
- `Campaign/<кампания>/Kenshi_Отряд.md` $\le$ 15 000 символов (LF).
- `Campaign/<кампания>/Kenshi_Канва.md` $\le$ 10 000 символов (LF).
- Суммарный объем динамического горячего набора: $\le$ 37 000 символов (LF).

Статический документ кампании:
- `Campaign/<кампания>/Kenshi_Режимы_и_методика.md`: содержит методологию оценки, правила прокачки и глоссарий; не изменяется в регулярном игровом цикле (правки только по явному решению игрока) и не входит в суммарный динамический лимит 37 000 символов.

Метод подсчета символов: нормализованный подсчет по LF (`python -c "print(len(open(path, encoding='utf-8').read().replace('\r\n', '\n')))"`).
