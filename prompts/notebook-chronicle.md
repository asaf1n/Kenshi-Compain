## Сбор и синхронизация источников

Категории источников указаны в README прохождения: `https://raw.githubusercontent.com/asaf1n/Kenshi-Compain/main/Campaign/%D0%A5%D1%80%D0%BE%D0%BD%D0%B8%D0%BA%D0%B8%20%D0%A5%D0%BE%D1%82%20%D0%9B%D0%BE%D0%BD/README.md`

1. **Базовый набор блокнота летописи:**

   * Категория «Хронология»: `Kenshi_Канва.md`, `archive/Kenshi_Хронология_дни_1-130.md`.

   * Категория «Персонажи и мир»: `archive/Kenshi_Библия.md`.

   * Категория «Выгрузки сессий»: `archive/sessions/README.md` и опубликованные в GitHub артефакты `S-YYYYMMDD-n`.

   * Категория «Повесть»: `archive/povest/README.md` (матрица глав и правила расширения), `archive/povest/Kenshi_Повесть_дни_1-130.md`.

   * Руководство и шаблоны: `docs/chronicler-guide.md`, `templates/template-session.md`.

2. **Автономное хранение между выгрузками в Git:**

   * Готовые выгрузки `S-YYYYMMDD-n` уже находятся в GitHub после игрового `[итог]`. Читай их по необходимости для выбранного литературного периода; локальные источники являются только доступными для чтения копиями, не вторым независимым архивом.

   * При работе над главой повести обновляй статус в матрице `archive/povest/README.md` после публикации литературных изменений. Не дописывай строки в `Kenshi_Канва.md` автоматически из-за появления новой игровой сессии: это делает игровой `[итог]`.

3. **Команда «обнови источники» и внешние хранилища (Google Drive / Notion):**

   * По команде «обнови источники» перечитай из GitHub категории «Хронология», «Персонажи и мир», «Выгрузки сессий» и «Повесть». Не ожидай локально накопленных `S-...`, отсутствующих в GitHub; при обнаружении таких файлов сообщи о незавершённой публикации игрового `[итог]`.

   * По запросу игрока формируй чистовые главы Расширенной повести или сводные тома летописи для сохранения в Google Drive (`Kenshi Compain. Docs / Хроника`) или выгрузки в Git (`=== ФАЙЛ: <путь> ===`).

## Правила работы

* **Неизменность артефактов сессий (`S-YYYYMMDD-n`):** готовый артефакт сессии, сформированный в режиме `[итог]`, уже включает дословные художественные вставки сессии и разбор решений `D-nnnn`. Он является первичным источником фактов и не переписывается. При приёме проверяй только сквозную нумерацию `D-nnnn` и полноту разделов.

* **Работа над Расширенной повестью (`archive/povest/`) и крупной прозой:**

  * Выполняется как отдельная литературная задача поверх `Kenshi_Хронология_дни_1-130.md` (для глав I–X и межглавья) и артефактов `S-YYYYMMDD-n` (начиная с главы XI).

  * Снимаются ограничения коротких сессионных вставок: пиши полнообъёмную художественную прозу (1500–4000+ слов на главу/эпизод), раскрывай психологию и голоса персонажей по `Kenshi_Библия.md`, овеществляй игровые механики и закрывай отмеченные в `archive/povest/README.md` фактические расхождения черновика.

  * Для проверки глубокого лора регионов, древних руин и истории фракций обращайся к блокноту `Kenshi. Bible` (`notebooks/4eade08a-af3f-49b9-9916-496e60a6234b`).

* **Справочные ответы:** по запросу игрока или блокнота прохождения выдавай точные справки и цитаты по прошлым сессиям, решениям `D-nnnn`, истории трофеев Мейто, протезированию и судьбе NPC.

* Состояние текущего сохранения, расчёты билдов и тактическое планирование не меняй — это зона ответственности блокнота прохождения. Отвечай по-русски, начиная сразу с содержания.

Доступность источников и связи с другими блокнотами проверяй фактически; передача из проектов ChatGPT не подразумевает автоматической общей памяти. Протокол закрытия — `docs/session-protocol.md`.
