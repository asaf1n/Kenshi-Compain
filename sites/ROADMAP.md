# Sites / веб-приложение Kenshi Compain — единый план P2–P3

**Статус: только план.** Готовых React/HTML-виджетов и шаблонов приложения здесь нет. `sites/` — целевой отдельный веб-интерфейс; реализацию через OpenAI Sites или другую платформу и её доступные API выбрать после проверки. Возможности ChatGPT и Gemini Notebook Studio — **платформенные реализации**, не одинаковые обязательные функции.

## P2 — аналитика
- Графики развития Strength, Dexterity, Toughness, Melee Attack/Defence, владения оружием по **двум и более историческим снимкам**; выбрать персонажа, отряд и интервал; не интерполировать несуществующие значения.
- Фильтруемая/сортируемая таблица по персонажу, группе, роли, навыкам, фактической экипировке, ранениям и целевым билдам; сравнение нескольких бойцов с источником каждого значения.
- Сравнение групп (`Primaris`, `Secundus`, `Roaming`, `White Armor`) и готовности к **конкретному** сценарию. Не вводить универсальную непрозрачную оценку боеспособности.
- Представление маршрута и угроз с обозначением подтверждённых координат/фракций; текстовый эквивалент любого графика, таблицы и фильтра.

## P3 — постоянная игровая панель
- Глава/этап/фактический статус (`планируется`, `в пути`, `на объекте`, `отход`, `завершён`), задачи, открытые риски и текущий снимок.
- Тактическая развилка с вариантами выбора, отдельно подтверждение приказа и **фактического** результата. Никакого скрытого запуска игровых действий.
- Журнал наблюдений и `D-nnnn` с неизменёнными художественными вставками, видимые checkpoints, экспорт `S-YYYYMMDD-n.md` с проверкой полноты; черновики отделены от закрытого архива.
- Интеграция чтения `published/` с валидацией схемы, `game_time`, `branch_id`, `snapshot_id`; отличать откат/устаревший снимок от новой ветки. Операции записи в GitHub — подтверждаемые, идемпотентные и с обработкой конфликтов.
- Передача только завершённой сессии в **отдельный** литературный проект без изменения источника.

## Проектирование перед реализацией
1. Согласовать модель `snapshot`, `character`, `squad`, `stage`, `event`, `decision`, `checkpoint`, `session` и ссылки на первоисточники; определить хранение истории снимков.
2. Отделить read-only данные игры от утверждённых решений и от черновика сессии. Нормативный процесс — `docs/session-protocol.md`.
3. Выбрать стек, хостинг, интеграцию LLM и библиотеку карт после проверки платформы, без привязки шаблонов чата к API.
4. Реализовать поэтапно: P2 таблица → P2 графики → P2 карта → P3 панель/журнал → P3 экспорт и интеграции.

**Приёмка:** график воспроизводит только сохранённые снимки; фильтры не меняют данные; неутверждённое действие не становится результатом; архив воспроизводит сцену дословно или выдаёт ошибку полноты; отмена записи/обрыв связи не объявляется успешным сохранением; смена ветки отображается явно.
