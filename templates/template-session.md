# Шаблон режима: \[итог\]

## Назначение режима

Режим `[итог]` по отдельной команде игрока **готовит и непосредственно публикует в GitHub `main`** закрываемую сессию как `S-YYYYMMDD-n` вместе с необходимыми изменениями Канвы и рабочих документов. **Сама команда `[итог]` является разрешением на эту запись; повторное согласование коммита не требуется**, если полная сессия и факты проверены. Артефакт становится канонической записью **после успешного коммита, push и проверки публикации**, а не при генерации ответа. Промежуточные снимки продолжает обрабатывать `[ход]`.

В режиме `[итог]` **новые художественные тексты не сочиняются**: в раздел «Художественные вставки сессии» дословно переносятся все короткие лор-вступления (из `[глава]` / `[этап]`) и вставки событий (из `[ход]`), созданные по ходу сессии, после чего следует структурированный разбор сессии по решениям `D-nnnn`. На основе этих сохранённых в GitHub артефактов `S-YYYYMMDD-n` проект летописи **в любое время** может писать Расширенную повесть (`archive/povest/`), не участвуя в завершении игры и не принимая каждую сессию отдельно.

**Контроль полноты P0:** собирай `[итог]` из доступного диалога, подтверждённых `D-nnnn` и сохранённых контрольных точек по `docs/session-protocol.md`. Невозможно восстановить дословную сцену или цитату — **не выдумывай**, помечай результат как `НЕПОЛНАЯ ВЫГРУЗКА` и перечисляй пробелы; это черновик, пока не восстановлены исходники. Перед закрытием проверь уникальность `S-YYYYMMDD-n`, время, ветку и последовательность решений.

**Watermark и запись:** блоки «ПРАВКИ» — составляющие той же операции публикации архива в GitHub, а не просьба о будущем коммите. До успешного сохранения существующий `Сверено до:` не изменяется. Не двигай watermark через исторический пробел, не закрытый источниками; в арку не копируются оперативные числовые данные `published/`.

## Правила

1. **Идентификаторы:**

   * Сессия: `S-YYYYMMDD-n` (дата реального дня и порядковый номер сессии за день).

   * Решение: `D-nnnn` — сквозная четырёхзначная нумерация по всем выгрузкам прохождения (начиная с `D-0001`; последний использованный номер фиксируется в первой строке `Kenshi_Текущая_арка.md`).

2. **Художественные вставки сессии — дословно без изменений:**

   * В выгрузку включаются все короткие художественные вступления (`[глава]`, `[этап]`) и вставки событий со сценой и блоком `Игровое событие` (`[ход]`), написанные в ходе текущей сессии, строго в порядке появления и без переписывания.

3. **Разбор по решениям — очищенная структура:**

   * Из диалога сессии убираются служебные сообщения (проверка источников, технические команды) и отвергнутые без обсуждения черновики.

   * Сохраняются обстановка, суть тактического обсуждения, **дословные слова игрока, если доступна точная запись (иначе явно укажи отсутствие цитаты)**, финальный статус решения (`approved`, `rejected`, `proposed`, `superseded->D-nnnn`) и фактический исход в игре.

4. **Неизменность архива:** после сохранения артефакт `S-YYYYMMDD-n` не редактируется; любые поздние уточнения заносятся в раздел «Исправления к прежним выгрузкам» следующей сессии.

## Обязательная операция записи

1. Сверь текущий `main`, наличие будущего `archive/sessions/S-YYYYMMDD-n.md`, последние сохранённые `D-nnnn`, branch/time, текущие Канву и арку. Подготовь точный архив без новых сцен, с дословным текстом всех доступных вставок.
2. При полноте файла и непротиворечивых фактах создай `Campaign/<кампания>/archive/sessions/S-YYYYMMDD-n.md`, обнови строку в `Kenshi_Канва.md`, сохранённые решения/цели и watermark в `Kenshi_Текущая_арка.md` только там, где это действительно подтверждено. При незакрытом историческом промежутке watermark не продвигай за него, даже если новый `S-...` успешно добавлен.
3. Запиши архив и нужные правки **одним коммитом** в `main` без force-push; при изменении HEAD перед публикацией перечитай и пересогласуй состояние, не перезаписывай чужие изменения. Повторно прочитай опубликованный архив и Канву.
4. Если проверка полноты не пройдена — выдай статус **НЕПОЛНАЯ ВЫГРУЗКА**, вопросы и черновик; **не** сохраняй его как закрытый `S-...`. Если запись не поддерживается или GitHub недоступен, отдай файлы для ручной публикации, но не заявляй об успешном закрытии.
5. При успешном сохранении ответь кратко: `S-YYYYMMDD-n`, SHA коммита, граница канона и открытые нити. Полный текст архива показывай в чате лишь по запросу.

**Границы артефактов в следующем формате:** файл `S-YYYYMMDD-n.md` содержит только Markdown от первого YAML `---` после маркера `=== ВЫГРУЗКА ... ===` до разделителя `=== СТРОКА ХРОНОЛОГИИ ===` (не включая разделитель). Строка Канвы и правки документов — отдельные изменения файлов, не часть `S-...`. Маркеры `=== ... ===` используются для ручного пакета только при невозможности прямой записи.
