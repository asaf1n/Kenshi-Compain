# Шаблон режима: [итог]

Режим `[итог]` фиксирует сессию: журнал фактов и решений, повествование сессии, правки рабочих документов и строку Канвы. Вызывается в конце сессии и для промежуточной фиксации; повторный вызов выпускает полную обновлённую запись с тем же идентификатором.

## Поток данных

1. Игра → конвертер → GitHub → оба блокнота: выгрузка игры (`published/`) и канон прохождения приходят в блокноты источниками по спискам README прохождения.
2. Между выгрузками в Git рабочее состояние канона живёт в источниках блокнотов. У каждого документа один владелец:

| Документ | Владелец между выгрузками в Git | Где лежит |
|---|---|---|
| Текущая арка, Отряд | блокнот ведения игры | его источники |
| Журналы сессий `S-…`, повествования, главы | блокнот хроники | его источники |
| Канва | блокнот хроники | его источники |
| Выгрузка игры `published/` | конвертер | источники обоих блокнотов, только чтение |

3. Git обновляется вручную: игрок запрашивает «выгрузка для Git» в блокноте ведения игры, сохраняет пакет в `inbox/` локального репозитория и запускает задание оркестратора. После коммита блокноты по команде «обнови источники» принимают канон из GitHub.

## Правила записи

1. **Идентификаторы**: сессия `S-YYYYMMDD-n`; событие `E-YYYYMMDD-n-nn`; бит `B-YYYYMMDD-n-nn`; решение `D-nnnn` — сквозная нумерация. Следующий номер решения — максимальный `D-` в журналах блокнота хроники плюс один; блокнот ведения игры уточняет его запросом к блокноту хроники.
2. **Источник и достоверность** у каждого события: `save` | `screenshot` | `player` | `inferred`; `confirmed` | `probable` | `hypothesis`. Числа — из выгрузки или слов игрока.
3. **Статус решения `approved`** ставится только по словам игрока; предложения компаньона — `proposed`; отклонённые варианты записываются с причиной.
4. **Слова игрока** приводятся дословно с привязкой к `E-`, `D-` или персонажу.
5. **Журнал и повествование разделены**: журнал содержит факты; повествование — художественная интерпретация битов.
6. **Пустой раздел** помечается «—» и остаётся в записи.
7. **Машинные блоки** выдаются простым Markdown с маркерами `=== … ===`, без интерактивных элементов и иллюстраций: по ним сохраняются источники и собирается пакет для Git.

## Сохранение после подтверждения игрока

Блокнот ведения игры через подключение `@Gemini Notebook`:
1. Добавляет в блокнот хроники источник «S-YYYYMMDD-n — Day N HH:MM» с блоками ЖУРНАЛ и ПОВЕСТВОВАНИЕ; при повторном `[итог]` той же сессии до начала следующей заменяет этот источник; дальнейшие уточнения идут разделом «Исправления» следующих журналов.
2. Заменяет свой источник «Текущая арка» полным текстом из блока ПРАВКИ, включая первую строку watermark.
3. Передаёт строку из блока КАНВА в блокнот хроники; блокнот хроники дописывает её в свой источник Канвы.
4. Сообщает игроку одной строкой, что сохранено. Если сохранение не удалось, называет шаг и выдаёт блоки для ручного добавления.

## Выгрузка для Git

По команде «выгрузка для Git» блокнот ведения игры собирает один пакет:

````markdown
=== ПАКЕТ ДЛЯ GIT · Day N HH:MM · сессии <S-первая> — <S-последняя> ===
=== ПРАВКИ: Kenshi_Текущая_арка.md ===
<полный текст рабочего источника>
=== ПРАВКИ: Kenshi_Отряд.md ===
<полный текст рабочего источника>
=== ПРАВКИ: Kenshi_Канва.md ===
<полный текст Канвы из блокнота хроники>
=== ЖУРНАЛ S-… ===
<журналы сессий из блокнота хроники, которых нет в Канве репозитория>
=== ПОВЕСТВОВАНИЕ S-… / ГЛАВА … ===
<художественные файлы блокнота хроники, которых нет в репозитории>
=== КОНЕЦ ===
````

Состав пакета определяется сравнением с источниками из GitHub: в пакет входят сессии и файлы хроники, отсутствующие в Канве репозитория. Журналы и файлы хроники берутся запросом к блокноту хроники через `@Gemini Notebook`.
